Twemoji-Mozilla — attribution and licence
==========================================

Baldr bundles `baldr/assets/fonts/Twemoji-Mozilla.ttf` as the colour
emoji font for the runa text backend. It is embedded in every Baldr
binary and sits behind every family the toolkit draws with, so an
emoji in any text renders in full COLRv0 colour without the app
asking for anything.

Artwork
-------
The emoji glyphs are derived from **Twemoji** by Twitter, Inc. and
contributors (now part of the open-source community). Twemoji
artwork is licensed under the Creative Commons Attribution 4.0
International licence (CC-BY-4.0).

  https://creativecommons.org/licenses/by/4.0/

Required attribution: "Twemoji by Twitter, Inc. and contributors —
CC-BY 4.0 — https://twemoji.twitter.com".

Apps that ship Baldr binaries are redistributing the Twemoji
artwork; an attribution line in your app's About / credits / docs
satisfies the CC-BY-4.0 notice requirement. This applies whether or
not the app ever draws an emoji: Odin's `#load` embeds the bytes at
compile time, so they are in the binary either way.

Build
-----
The specific binary bundled here is the **Twemoji-Mozilla** build —
a TTF assembling Twemoji's SVG sources into COLRv0 layered glyphs
suitable for shipping inside an OpenType font. The build tooling is
maintained by Mozilla under the Apache 2.0 licence at:

  https://github.com/mozilla/twemoji-colr

The artwork licence (CC-BY-4.0) governs redistribution; the tool
licence (Apache 2.0) only matters if you regenerate the font.

Why bundle
----------
Baldr's runa backend reads COLRv0 colour glyphs and composites them
into an RGBA atlas page. Shipping a known-good COLRv0 font in-tree
means emoji look the same on every platform without depending on the
host OS's emoji set (which is CBDT/sbix on macOS, COLRv1 on modern
Linux, and absent or out of date on many Windows installs).

Not drawing emoji
-----------------
There is no switch, and nothing to turn off: the font is a fallback
behind the others, so it costs nothing until a codepoint needs it —
no atlas page is allocated and no glyph is rasterised. The bytes are
still in the binary, which is why the attribution above applies
whatever the app draws.

The other fonts
---------------
Inter (`InterVariable.ttf`, `InterVariable-Italic.ttf`) and JetBrains
Mono (`JetBrainsMono-Variable.ttf`) are embedded the same way, under
the SIL Open Font Licence 1.1 — see `InterVariable-OFL.txt` and
`JetBrainsMono-OFL.txt` beside this file. The OFL asks that its
notice travel with the font, which those files are.

An app may replace the UI or mono face at build time with
`-define:BALDR_UI_FONT=…` or `-define:BALDR_MONO_FONT=…`, in which
case that font's licence is the app's to carry and the matching file
here no longer describes what shipped.
